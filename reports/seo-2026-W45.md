## Technical Audit

### 🔴 High: host mismatch between apex and www (new finding)

I checked the live site with curl:

- `https://passdropit.com/*` returns a **307 (temporary) redirect** to `https://www.passdropit.com/*`.
- On www, every canonical, the sitemap `<loc>` URLs and the robots.txt `Sitemap:` line point back to the apex, `https://passdropit.com/...`. `SITE_URL` falls back to apex in `sitemap.ts`, `robots.ts` and `blog/[id]/page.tsx`, and the Vercel env var isn't set to www.
- The sitemap submitted in GSC is `https://www.passdropit.com/sitemap.xml`, which lists apex URLs that all redirect.

Every indexable page therefore canonicalises to a URL that temporarily redirects back to itself, so Google gets contradictory signals. This is the likely driver of the **"Page with redirect" count rising from 49 to 51**. GSC currently shows apex URLs as the indexed versions, which means Google is following the canonicals. The cleanest fix is to make apex the primary domain in Vercel, with www → apex as a 308. The alternative is to set `NEXT_PUBLIC_PASSDROPIT_SITE_URL=https://www.passdropit.com` and resubmit the sitemap. **Added to backlog.**

### 🔴 High: unknown blog slugs return a soft 404 (new finding)

`https://www.passdropit.com/blog/does-not-exist-xyz` returns **200** with `<title>Blog — Passdropit`, `robots: index, follow` and a self-referencing canonical. `src/app/blog/[id]/page.tsx` renders an empty layout when `getPost()` returns null instead of calling `notFound()`. This is a likely source of the **7 Soft 404s** in GSC. **Added to backlog.**

### 🔴 High: still open from W44

- **User link-gate pages are indexable.** `/goldene` returns 200 with `robots: index, follow`, and `src/app/[slug]/page.tsx` still exports no robots metadata. In GSC, "Duplicate without user-selected canonical" is at 32 and "Indexed, though blocked by robots.txt" at 6, both unchanged. `/download/go/WBnQPLJe` picked up 182 impressions. **Caveat to add to the task:** the only page-1 core-keyword ranking (`dropbox password protected link`, pos 7.1) comes from these user pages. Noindexing them will remove it, so the retitle of `how-to-share-and-protect-a-dropbox-link` (Medium backlog) should ship at the same time.
- **Broken `/register` CTA, now in 5 posts.** `https://www.passdropit.com/register` currently redirects (307) to `/invalid-link`. The **new Lightroom post (2026-11-01) repeats the bug**, and the two 2023 posts `how-to-create-a-google-drive-link` and `how-to-share-and-protect-a-dropbox-link` have it too. Affected lines in `src/lib/blog/posts.ts`: 9, 45, 81, 297 and 333. The three newest posts also have 2× absolute `https://www.passdropit.com` links each, and line 261 has `.../user/prosignup`. Backlog item updated.

## Keyword Opportunities

1. **`dropbox password protected link`** (43 impressions, pos 7.1 via user pages). This is the strongest signal in the account. Google already associates passdropit.com with the query. The planned retitle of `how-to-share-and-protect-a-dropbox-link` should target it exactly and must ship alongside the noindex fix so the ranking moves to the blog post instead of being lost.
2. **`share dropbox folder with multiple users`** / **`share a dropbox folder with anyone`** (22 and 20 impressions, pos ~44). These are new long-tail variants for the share-a-folder post, which is the site's biggest impression asset (424 impressions, 0 clicks). They support the planned refresh: add a "with multiple users" H2 and a "share with anyone (without a Dropbox account)" H2.
3. **`dropbox password expired` / `how to reset dropbox password`** (pos 27–28, 34–40 impressions each). The intent is navigational and the conversion value is low. A light refresh to get onto page 2 or 3 is fine, but this isn't a priority.
4. **Competitor watch: lock.pub** (new). It publishes "How to Password Protect Dropbox Shared Links (Free Alternative)" in several languages, including Bengali. It uses the same wrapper model as Passdropit and targets Passdropit's core keyword plus a "free" modifier. Its localisation also matches Passdropit's SEA and South Asia audience (Indonesia #1, India #3). Worth considering an **Indonesian-language** version of the core how-to post.
5. **Papermark** still holds 3+ results for `password protect dropbox link`. Peony now ranks for both Google Drive keywords with "7 methods" listicles. A comparison or listicle-format post, "How to password protect a Google Drive link: 5 methods compared", would match the SERP format. That fits the existing queued idea "Does Google Drive have password protection?".
